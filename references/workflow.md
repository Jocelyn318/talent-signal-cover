# 内容、确认与项目记录

## 主 agent 的第一步

理解文章真正的观点转变、问题及双方关系。未知信息标记不确定，不编造人物身份、引语、年份或案例。标题未定时提供候选，不把提案文案合进背景。

经验：人才密度文章实际谈供需匹配，不应画密集小人或晶体比例；AI Native Organization 讨论个人从职能执行者转向保有完整上下文、调动能力并对结果负责的 Loop Owner，不是“一个人亲手做所有任务”或“升职成老板”。这些只是案例，不代替阅读下一篇正文。

提案模板：

1. 内容理解：核心关系，哪些信息不打算画进封面。
2. 候选文案：标题、副标题、强调词、建议断行（独立文本）。
3. 视觉方案：一句画面、元素之间的关系、主体动作与空间、留白。
4. 风格：预期未来复古表现与配色；用户未提供参考时，不假装已有参考或强套旧图。
5. 确认：提案版本／候选编号，请用户选择并提供参考图，说明需要的部分、排除项和目的，然后等待。

## 生图前：参考与意图确认

逐张实际查看用户参考，记录：文件路径、角色（元素／关系、构图、背景空间、材质、配色、编辑目标）、借用项、排除项、表达目的。角色可组合，但不自动继承未指定部分；配色必须单独注明来源。比如借“递归空间”不等于借绿底，借“手与电脑近景”不等于借真人脸、品牌或窗帘。

主 agent 用简短最终意图包说明内容隐喻、主体动作、构图与留白、参考取舍、未来复古处理、配色、安全区及锁定项，再等用户确认。如果用户消息已明确授权具体取舍与生图，记录该授权后执行，不增加形式化确认。选择方案但参考尚未到位时状态为 awaiting_references；不把“确认 A”自动解释为免参考。用户可明确授权本次不提供参考。

## 项目记录

在用户工作目录建单期记录（Markdown 或 JSON），不写进 Skill 安装目录。至少保存：原始内容／来源、提案版本、状态（awaiting_confirmation、awaiting_references、confirmed 或 awaiting_feedback）、用户确认原话、选定方案、独立文案、视觉概念、逐图参考取舍及目的、配色来源、锁定项、执行子 agent、生成／编辑模式、实际提示词、输入输出版本、反馈及其认可范围。

新请求没有明确对应的已确认方案时，不生图。用户确认 A 后不额外生成 B、C；拒绝 A 后不能自己假设 B 已获确认。明确“这张保留构图换成蓝底”是在已有方案内的编辑授权。改核心隐喻要重新确认。

## 生图交接

主 agent 定内容和设计，具体生图及局部改图由一个执行子 agent 负责。交接完整意图包：已确认版本和授权原话、内容关系、参考路径及逐图取舍目的、配色、编辑目标、锁定项、无字要求、中央裁切边界、输出路径。要求子 agent 读取本技能及可用 imagegen 技能，实际查看输入，只执行已确认方案，并将不同参考统一渲染为未来复古，不能退回参考原本的写实或其它风格。主 agent 同时准备记录或独立文案，收到结果后检查图像、隐喻和裁切，不凭子 agent 的完成声明验收。

不并行让多个 agent 改同一图。子 agent 返回实际图片、完整提示词、参考用途和偏差。无委派能力时说明阻碍，由用户决定是否授权主 agent 代做。

提示词写清：无字、主题关系、主体、构图、允许变化、必须保留、材质、颜色、不继承的参考背景色、标题净空。选择最相关的少量参考实际传入工具，避免把 15 张全部堆入。本次改背景不得覆盖已确认文字。

保存旧版，新文件按版本命名。检查输出与提示是否有偏移，诚实记录；生成工具不是确定性图层编辑器。快速 demo 只做一张，不擅自精修多轮。仍需检查安全区；未通过时明确标注待修，不能称为可直接发布的最终封面。

## 反馈与验收

分开记录内容、隐喻、构图、配色、风格观感、排版和整体认可。“好看”不证明概念已被准确读出；“元素还可以”不等于颜色通过。用户明确全局规则可以提升为通用偏好，其余留在本期。

仅要无字背景时到此交付，不自动叠字；需要可编辑封面时调用本地编辑器。文字、背景、锁定项互不覆盖。对已锁字段的 AI 更新应跳过并说明。
